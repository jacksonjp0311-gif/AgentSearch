# AgentSearch 1.0.0rc4 — Windows and agent integration release candidate

The existing RC3 source was retained, repaired and prepared for public use.
All twelve discovered RC3 downloads had SHA-256
`c5ecb7a0fba640c1497845172fcc68cf5d4065fea5632f980d15d1288877a043`.
The extracted source matched all archive files and contained no Git history.
The first commit preserves that original distribution; later commits describe repairs.

## Repaired and checked

- Native Windows stable-file reads were falsely classified as changing because
  pathname and descriptor ctime fields differed. Cross-API identity now compares
  birth time where Windows exposes it, retaining size, modification time, identity
  and separate descriptor-before/after ctime checks. POSIX ctime checks remain.
- Windows DOS short-name aliases are expanded before scope checks without following
  junction targets. A dedicated regression verifies both allowed reads and
  excluded-directory rejection; path oracle fixtures use canonical names.
- Evidence capture now stops if a file grows beyond its byte budget.
- PowerShell supports an explicit interpreter without assuming PATH or py launcher.
- Fault-injection fixtures replace files after handles close on Windows, account
  for native newlines, and close unrelated SQLite connections before cleanup.
- JSONL now supports `verify` as well as its original operations.
- Topology includes newly added modules and package imports; hashes and actual AST
  edges are tested. Sealing includes skill and maintenance executable sources.
- The original RC3 manifest's `1.0.0-rc3` disagreed with runtime `1.0.0rc3`.
  RC4 uses one PEP 440 version consistently and regenerates its manifest.

The initial native run collected 81 tests: 44 passed, 28 failed, 6 errors and
3 skips. Those failures are not concealed by historical portable passes.
Current native suite results are in [windows-rc4.json](../validation/windows-rc4.json).
Sealed verification is rerun after final packaging and CI verifies the committed
manifest on Windows and Linux with Python 3.11, 3.12 and 3.13.

## Measured stress workload

Windows / Python 3.12.14 / SQLite 3.53.1: **10,000 checked requests, 32 concurrent
logical clients**, independent connections to a local SQLite WAL index. All passed.
The 64-file synthetic workload mixed all five tools, completed in **55.509s**,
and measured request latency **p50 168.652ms / p95 280.659ms / p99 323.529ms**.
Peak Python-traced memory was **17,586,878 bytes**, not process RSS; tracing adds
overhead. This is not a whole-disk, MCP-process-load or hard-real-time claim.
See [stress receipt](../validation/stress-rc4.json) and `examples/stress.py`.
The separate seeded mutation workload is recorded in
[soak receipt](../validation/soak-rc4.json), using `examples/reliability_soak.py`.

## Integration and release scope

All five tools were registered and invoked through the installed Hermes
PluginContext and registry in an isolated fixture profile. No model was called.
The prepared Pegasus adapter binds the host-selected project, prevents private
memory directory access and reserves refresh for the operator. Source retrieval
has not been wired into Pegasus's production acceptance receipts. See
[the integration plan](../PEGASUS_INTEGRATION.md).

This remains **RC4**, not stable 1.0.0. Real model task improvement, a hostile-race
security audit, physical power-loss durability, network filesystems, macOS and
cloud-sync reliability are unverified. Local Windows symlink creation required
privileges unavailable to the test process; those tests are explicitly skipped.
Junction and extended-path tests execute separately. Plain paths beyond MAX_PATH
depend on Windows policy; use the explicit `\\?\` form when that policy is disabled.
Do not change machine policy automatically. Indexes are private derived state.

No credentials, private databases or model runtime are part of this release.
The supplied MIT license and provenance notices are preserved. The original
infographic is labeled historical because its example API and claims are stale.
